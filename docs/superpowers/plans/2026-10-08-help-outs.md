# Helping Out (Aushelfen), Step 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An employee of facility A can help out in facility B on single days. B plans them in a helper column; A sees "Aushilfe in B"; hours stay on one account; B's tablet lets them stamp.

**Architecture:**
- New table `help_outs` (employee × facility × month) gives a helper column.
- New nullable column `entries.help_facility_id` marks entries planned in another facility's plan.
- `loadEntries`' facility filter splits:
  - `homeFacilityId`: the old `facilityId` meaning, renamed;
  - `planFacilityId`: what one facility's plan contains.
- Cell ownership ("one day, one facility") is enforced in the entries service and reused by plan, release, revert, notifications and the tablet.

**Tech Stack:** Nuxt 4 (Nitro), Drizzle ORM + better-sqlite3, zod, Vitest, Nuxt UI 4.

**Spec:** docs/superpowers/specs/2026-10-07-help-outs-design.md

## Global Constraints

- UI German, code English. All texts in `app/locales/de.ts`. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Services take `db` first, then `facilityId` (the acting facility). Routes pass `user.facilityId` from `requireAdmin` / `requireFacility`.
- With no help-outs, the app behaves exactly as before. Every existing test keeps passing.
- A help-out entry has `help_facility_id` = the facility whose plan it belongs to, and this is never the employee's home facility. Home entries have null.
- One day, one facility: all entries of one employee on one date share the same `help_facility_id`.
- Error codes:
  - `help_out_exists` (409)
  - `help_out_has_entries` (409)
  - `help_out_not_found` (404)
  - `cell_taken` (409): a helper's day belongs to another plan
  - `cell_helps_elsewhere` (409): the home facility writes a non-absence over a help-out day
  - `help_code_not_allowed` (400): an absence code in a helper cell
  - `employee_not_found` (400): a cell whose person is neither staff nor a helper this month
- B's Leitung never receives a helper's balances, leave, contract data, time records or warnings other than coverage.
- New routes are classified in `tests/api/permissions.test.ts`.
- Migration `0021_help_outs` is generated with `npx drizzle-kit generate --name help_outs`. It must be plain `CREATE TABLE` plus `ALTER TABLE entries ADD help_facility_id` with no table rebuild, because it runs on the user's real data. If drizzle wants a rebuild, write it with `--custom`.
- Old release snapshots have no `helpFacilityId` on entries and no `helpFrom` on employees. Read missing values as null.

## Review Focus

1. **A's Leitung on a help-out day.** A's Leitung clicks a day on which their employee helps out in B and enters a shift. This must be refused (`cell_helps_elsewhere`) without touching B's entries. Entering "Krank" must replace B's entries, log in both facilities, and show as pending in B. Test: Task 2.
2. **Discard in either facility around a help-out day.** Discarding in B must never delete A's entries. Discarding in A must never delete B's help-out entries or restore over them. Test: Task 3.
3. **A third facility C.** C must not see, change or remove B's helper or A's marker. Ids from B answer `*_not_found`. Test: Task 7.
4. **The tablet.** B's tablet with the helper's correct PIN works on a day planned in B. On another day it gives `employee_not_found` before the PIN is checked. A's tablet keeps working for them. Test: Task 4.
5. **Moving the helper into B.** After the helper moves into B, their B entries become ordinary home entries, the `help_outs` rows for B are gone, and nothing is pending or lost. Test: Task 1.

**Interfaces:**
- Produces:
  - `EntryFilter { homeFacilityId?: number; planFacilityId?: number; … }`. `planFacilityId: F` means `help_facility_id = F OR (help_facility_id IS NULL AND employees.facility_id = F)`.
  - `listHelpers(db, facilityId, year, month): HelperDto[]`
    - `HelperDto { helpOutId: number; employeeId: number; name: string; shortName: string; fromFacilityId: number; fromFacility: string }`
    - ordered by name
  - `helpCandidates(db, facilityId, year, month): HelpCandidateDto[]`
    - `HelpCandidateDto { employeeId: number; name: string; shortName: string; facilityName: string }`
    - active employees of other facilities who are employed in the month and are not yet helpers that month
  - `addHelpOut(db, facilityId, input: { employeeId: number; year: number; month: number }): number`
    - 400 `employee_not_found` for own staff or an unknown id
    - 409 `help_out_exists`
  - `removeHelpOut(db, facilityId, id: number): void`
    - 404 `help_out_not_found` for another facility's row
    - 409 `help_out_has_entries` while the helper has entries with `help_facility_id = facilityId` in that month
  - `isHelperOn(db, facilityId, employeeId, date): boolean` (has a `help_outs` row for that month)

  - `server/services/plan.ts`:
    - coverage and warnings per the spec;
    - week totals and balances for staff only (totals include their help-out hours);
    - no actuals for helpers;
    - `MonthPlanDto` gains `facilityId: number` and `facilityNames: Record<number, string>`;
    - `MonthPlanAdminDto` gains `helpers: HelperDto[]` and `helperBusy: Record<number, IsoDate[]>` (days of a helper that belong to another plan);

  - `server/services/revert.ts`:
    - restores only entries owned by this facility's plan, and inserts helper entries with `helpFacilityId = facilityId`;
    - skips a cell whose day now belongs to another plan;
    - deletes only this plan's entries of the cell.
  - `server/services/notifications.ts`: diff without marker entries, so helpers are told about B's changes and A does not re-tell them.
  - `shared/types/api.ts`: `EmployeeColumnDto.helpFrom?: string | null`, plus the DTO additions above.

- Produces: `ownEntries(facilityId, entries)`, exported from `shared/domain/releaseDiff.ts`. It drops entries whose `helpFacilityId` is set and is not `facilityId`, treating undefined as null. Task 5 uses it.
