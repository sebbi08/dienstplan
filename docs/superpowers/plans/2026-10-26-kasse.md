# Kasse – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cash books per facility and group (several per scope): monthly sheets like the „Kassenblatt“, receipts, transfers between boxes, month closing with Träger-only reopening, audit log, print page and CSV for Excel — for Leitung and Träger only.

**Architecture:** Pure money/sheet/closing/CSV logic in `shared/domain/cash*.ts`; one service module per concern in `server/services/cash*.ts` working on five new tables (migration 0054); routes under `server/api/cash/…`; pages `/cash`, `/cash/[id]/[year]/[month]` and a print page; own menu entry „Kasse“.

**Tech Stack:** Nuxt 4, Nitro, drizzle-orm + better-sqlite3, Nuxt UI 4, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-26-kasse-design.md`

## Global Constraints

- UI German, informal „du“; code, identifiers, comments, commits English. No Docker/CI changes. No new npm dependencies.
- Never run `npm install`/`npm ci` or npx downloads (drizzle-kit is local). Never kill processes by image name; stop only own PIDs. Port 3000 and `.data/app.db` stay untouched — own checks on 127.0.0.1:3100 with `DATABASE_PATH`/`MIGRATIONS_DIR` on scratch copies.
- Branch `claude/cashbook` (from `7234f2d`, newest migration `0053_setup_hidden`); one migration `0054_cashbook` (`npx drizzle-kit generate --name cashbook`; journal `when` larger than 0053's).
- Amounts are integer cents everywhere (DB, API, domain); display „1.234,56 €“; input accepts comma or dot, max two decimals.
- Entry: date inside the sheet's month, not in the future, not before the box's start month; amount 1 … 100 000 000 cents; purpose 1–200 chars (trimmed). Start balance ≥ 0.
- Box: name 1–60 chars, unique per facility (case-insensitive); kind `cash` („Bar“) | `account` („EC/Konto“); scope = facility (groupId null) or one group of the facility.
- Numbers are not stored: per month, separately for income/expense, ordered by date then id.
- Transfer texts: expense „Umbuchung an ‹Ziel›: ‹Text›“, income „Umbuchung von ‹Quelle›: ‹Text›“; both rows share `transferId`; edit/delete always both.
- Closing: month must be over (or today is its last day) and the previous month closed (start month has none). Closed = no create/update/delete of entries dated in it (incl. transfers on either side), no change of start month/start balance. Reopen: Träger only, reason 1–200 chars, reopens that month and all later closed months of the box.
- Negative-balance hint only for `cash` boxes: running balance below 0 on any day of the month → `negative: true`.
- Receipts: `checkedDocumentFile` (JPG/PNG/PDF, `MAX_DOCUMENT_BYTES`) and the upload helpers of `server/lib/documentHttp.ts`; stored as blob in the DB.
- Rights: `requireAdmin(` for everything except reopen (`requireProvider(`); a box of another facility → 404 `cash_box_not_found`. Mitarbeiter/Tablet 403.
- Menu: own entry „Kasse“ (`/cash`) in the always-visible main row after „Kinder“ and before „Kalender“; same place in the phone menu's main group. Not under „Mehr“.
- Tests: `npx vitest run <file>`; all `npm test`; types `npm run typecheck`; build `npm run build`.

## Review Focus

1. A transfer whose date lies in a month closed in only one of the two boxes → 409 `cash_month_closed`, nothing written in either box. → Task 2 test.
2. Deleting the oldest income of a month renumbers the rest (2. becomes 1.), and the next month's start balance changes accordingly. → Task 1 + Task 2 tests.
3. Reopening March when April and May are closed → March, April, May open; log has one „wieder geöffnet“ line with the reason. → Task 3 test.
4. Amount input „12,5“ → 1250 cents; „12,555“, „-3“, „0“, „abc“ rejected. → Task 1 test.
5. A Leitung requesting a box, entry or receipt of another facility → 404, not 403 (no existence leak). → Task 2/3 tests.

### Task 1: Domain (money, sheet, closing rules, CSV)

**Files:** Create `shared/domain/cash.ts`, `shared/domain/cashCsv.ts`; Test `tests/domain/cash.test.ts`, `tests/domain/cashCsv.test.ts`

**Interfaces (produces):**
- `type CashKind = 'cash' | 'account'`, `type CashDirection = 'in' | 'out'`
- `parseCents(text: string): number | null` (comma/dot, ≤ 2 decimals, > 0 — returns null otherwise), `formatCents(cents: number): string` („1.234,56 €“, negative with „−“)
- `interface CashEntryFact { id: number; date: IsoDate; direction: CashDirection; cents: number; purpose: string; hasReceipt: boolean; transferId: number | null }`
- `monthSheet(input: { kind: CashKind; startBalance: number; startMonth: { year; month }; year; month; entries: CashEntryFact[] /* all entries of the box up to the month's end */ }): { opening: number; income: number; expense: number; closing: number; negative: boolean; rows: (CashEntryFact & { number: number; balanceAfter: number })[] }` — rows only of the month, ordered by date then id; `number` per direction.
- `canClose(input: { year; month; today: IsoDate; startMonth; closed: Set<string> /* 'YYYY-MM' */ }): 'ok' | 'not_over' | 'previous_open' | 'already_closed' | 'before_start'`
- `monthsToReopen(year, month, closed: Set<string>): string[]` (that month and all later closed ones, sorted)
- `cashCsv(input: { boxName; from: { year; month }; to: { year; month }; opening; closing; rows (as monthSheet rows, over the range) }): string` — `;`-separated, BOM `﻿`, CRLF, header lines Kasse/Zeitraum/Anfangsbestand/Endbestand, then columns `Datum;Nr.;Art;Betrag;Verwendungszweck;Beleg;Bestand` (dates `dd.mm.yyyy`, amounts `1234,56` without thousands separator and without „€“, Art „Einnahme“/„Ausgabe“, Beleg „ja“/„nein“); fields with `;`, `"` or line breaks quoted with doubled quotes.

- [ ] Failing tests: parseCents table (Review Focus 4: „12,5“→1250, „12.50“→1250, „1.234,56“→null: thousands separators are rejected), formatCents; monthSheet over three months with carry-over, numbering per direction, renumbering after removing an entry (Review Focus 2), negative only for cash, start month opening = startBalance; canClose each outcome; monthsToReopen; CSV quoting, BOM, comma amounts.
- [ ] Implement → pass → commit `feat: cash book domain`.

### Task 2: Data, boxes, entries, transfers, log

**Files:** `server/db/schema.ts` (+ migration 0054), Create `server/services/cashBoxes.ts`, `server/services/cashEntries.ts`, `server/services/cashLog.ts`, routes `server/api/cash/boxes.get.ts`, `boxes.post.ts`, `boxes/[id].put.ts`, `boxes/[id].delete.ts`, `boxes/[id]/[year]/[month].get.ts`, `entries.post.ts`, `entries/[id].put.ts`, `entries/[id].delete.ts`, `transfers.post.ts`, `transfers/[id].put.ts`, `transfers/[id].delete.ts`, `purposes.get.ts`; validation in `server/schemas.ts`; `tests/api/permissions.test.ts` (admin route list); `server/services/groups.ts` (deleting a group with boxes → 409 `group_has_cash_boxes`); DTOs in `shared/types/api.ts`; Test `tests/services/cashBoxes.test.ts`, `tests/services/cashEntries.test.ts`

**Tables:** `cash_boxes` (id, facility_id, group_id null, name, kind, start_year, start_month, start_balance, archived, sort_order, created_at); `cash_entries` (id, box_id, date, direction, cents, purpose, receipt_id null, transfer_id null, created_at, created_by); `cash_receipts` (id, facility_id, mime, data blob, name, created_at); `cash_closed_months` (box_id, year, month, closed_at, closed_by; pk box+year+month); `cash_log` (id, box_id, at, actor, action, detail). A transfer has no own table: both rows carry the expense row's id as `transfer_id`.

**Interfaces (produces):**
- `listBoxes(db, facilityId, today): CashBoxDto[]` (with `balanceToday`, `closedThrough: { year; month } | null`, `missingReceipts: boolean`, group name), `createBox/updateBox/deleteBox(db, actor, facilityId, …)`, `loadBox(db, facilityId, id)` (404 `cash_box_not_found`)
- `cashMonth(db, facilityId, boxId, year, month): CashMonthDto` (monthSheet result + box + `closed: { at; by } | null` + log lines of the month)
- `createEntry/updateEntry/deleteEntry`, `createTransfer/updateTransfer/deleteTransfer` — every write checks the closed months (409 `cash_month_closed`), archived box (409 `cash_box_archived`), start month (400 `cash_before_start`), future date (400 `cash_date_future`) and logs via `logCash(tx, boxId, actor, action, detail)`; transfers run in one transaction.
- `purposeSuggestions(db, facilityId, query): string[]` (most used first, max 8)

- [ ] Failing tests: CRUD + validation; unique name; group of another facility rejected; delete only without entries (409 `cash_box_has_entries`); transfer both rows / edit both / delete both; Review Focus 1 and 5; log lines with before → after; group delete blocked; permissions list updated.
