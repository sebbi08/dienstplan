# Notizen der Einrichtung – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A page „Notizen“ where the facility keeps a pin board and notes for single days, for the whole facility or one group; everyone in the facility (and the tablet) reads, writers with the new right „Notizen schreiben“ (facility or own group) write.

**Architecture:** Two new permission keys — `notes.view` (baseline: every account) and `notes.write` (new scoped bundle `notesWrite` in a new area `notes`, default on for Leitung with scope facility and Gruppenleitung with scope group). A new table `facility_notes`, a service `server/services/facilityNotes.ts` with four routes under `/api/notes`, and a page `app/pages/notes.vue` in the main menu and on the tablet.

**Tech Stack:** Nuxt 4, Nitro, drizzle-orm + better-sqlite3 (`npm run db:generate`, local drizzle-kit), Nuxt UI 4, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-09-notizen-design.md`

## Review Focus

- A Gruppenleitung editing or deleting a note of another group or of the whole facility: 403, nothing changed.
- A writer with scope „eigene Gruppe“ but without a group (Springer, no linked employee): every write 403 `notes_no_group`; reading works.
- A note id of another facility: 404 `note_not_found` for read-modify-delete.
- A deleted group: its notes show for the whole facility (FK `set null`) and stay editable by facility-scope writers only.
- „gilt bis“ exactly today still counts as current (expired only when before today, Berlin date).

**Interfaces:**
- Consumes: Task 1 keys and scopes.
- Produces:
  - Table `facilityNotes` = `facility_notes`: `id` pk, `facilityId` (→ facilities, cascade), `groupId` (→ groups, `set null`, nullable), `kind` text enum `['board','day']`, `date` text nullable, `validUntil` text nullable, `text` text, `createdAt`, `createdBy` (name), `updatedAt` nullable, `updatedBy` nullable; index on (`facility_id`, `kind`, `date`).
  - `export interface NoteDto { id: number; kind: 'board' | 'day'; groupId: number | null; groupName: string | null; date: IsoDate | null; validUntil: IsoDate | null; text: string; createdAt: string; createdBy: string; updatedAt: string | null; updatedBy: string | null; canEdit: boolean }`
  - `export interface NotesDto { board: NoteDto[]; expired: NoteDto[]; upcoming: NoteDto[]; past: NoteDto[]; pastHasOlder: boolean; groups: { id: number; name: string; color: GroupColor }[]; write: { facility: boolean; groupId: number | null } | null }` — `write` null without `notes.write` (and for the tablet); `facility` true for scope facility; `groupId` = own group for scope group (null if none).
  - `export interface NoteInput { kind: 'board' | 'day'; groupId: number | null; date: string | null; validUntil: string | null; text: string }`
  - Service (actor = the route's `FacilityUser`):
    - `listNotes(db, actor, filter: { group: 'all' | 'facility' | number; olderPast?: boolean }, today: IsoDate): NotesDto` — `board`: kind board with `validUntil` null or ≥ today, newest `createdAt` first; `expired`: board with `validUntil` < today, newest first; `upcoming`: day notes with `date` ≥ today ascending (then `createdAt`); `past`: day notes before today, newest date first, only the last 12 months unless `olderPast`; `pastHasOlder` true when older ones exist. Filter `facility` = `groupId` null only; a group id = that group's notes **and** the facility ones; another facility's group id → 404 `group_not_found`.
    - `createNote(db, actor, input, now)`, `updateNote(db, actor, id, input, now)` (kind may not change: 400 `note_kind_fixed`), `deleteNote(db, actor, id)`.
  - Rules: scope facility → any group of the facility or none; scope group → `input.groupId` must equal the own group (employee of `actor.employeeId`, its `groupId`), else 403 `forbidden`; no own group → 403 `notes_no_group`; update/delete a note whose current `groupId` is not the own group → 403 `forbidden`. Validation: text trimmed 1–1000 → 400 `note_text_invalid`; day needs a valid `date` → 400 `note_date_invalid`, board ignores/clears `date`; `validUntil` only for board, valid ISO, on create not before today → 400 `note_valid_until_invalid`; group of another facility → 404 `group_not_found`; note of another facility → 404 `note_not_found`. Names via the helper team meetings use (`actorName` in `server/services/formTemplates.ts`).
  - Routes: GET `/api/notes?group=&older=` → `requirePermission(event, 'notes.view', { allowTerminal: true, facility: 'active' })`; POST/PUT/DELETE → `requirePermission(event, 'notes.write', { facility: 'active' })`. `today` = Berlin date (`nowInBerlin(new Date()).date` as in teamMeetings).
  - Error texts (German): `note_text_invalid: 'Bitte gib einen Text mit 1 bis 1000 Zeichen ein.'`, `note_date_invalid: 'Bitte gib ein gültiges Datum an.'`, `note_valid_until_invalid: '„Gilt bis“ muss ein gültiges Datum ab heute sein.'`, `note_not_found: 'Diese Notiz gibt es nicht (mehr).'`, `note_kind_fixed: 'Die Art einer Notiz lässt sich nicht ändern.'`, `notes_no_group: 'Du kannst nur Notizen für deine eigene Gruppe schreiben – dir ist keine Gruppe zugeordnet.'`.
